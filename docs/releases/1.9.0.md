A new server, and a release about safety. The server is rewritten in Rust: it idles at about 2 MB of memory where the old one, on the JVM, held 130 to 200 MB, and its image is 22 MB instead of 289, small enough for a Raspberry Pi. It reads the same folders, ports and settings, so paired phones carry on as they were. A security review of the server and the apps found ways a stranger, a web page, another app or a crafted note could get at your notes or stop the app; this release closes them. Update both the server and the apps.

### Before you update

- **Update the server the usual way:** `docker pull ghcr.io/jglouis/korgnote-server:latest`, then the same `docker run` command as before. The ports, the variables and the two folders, your notes and `~/.korgnote-server`, are the same, and the certificate and paired devices in that folder are read as they are: no phone needs pairing again. `JAVA_TOOL_OPTIONS` no longer does anything, there being no Java. To go back, run `ghcr.io/jglouis/korgnote-server:1.8.1` instead.
- **Pairing a new device now asks you to press Allow on the computer** (see below). A phone that still has 1.8 waits only 15 seconds for that: press Allow quickly, or update the phone first.
- **The web app updates with the server,** as it is served by it. The Android app updates from the release page as before.

### Pairing

- **A pairing code alone no longer pairs a device.** After the phone scans the code, the Devices page shows *Pixel 8 asks to pair, from 192.168.1.42* with **Allow** and **Refuse**, and the phone waits until you press one, for two minutes at most. Another app on the phone can receive a code the camera reads, as the camera hands `korgnote://` links to whichever app asks for them; it can no longer pair with your computer in KorgNote's place. Allow only a device you are pairing yourself, right then.
- **The phone says what happened:** paired, *refused on the Devices page*, or *nobody allowed this device in time*. A refusal you did not make means someone else tried to pair: check the Devices page.
- **A pairing link from outside the app asks first.** A link opened from a web page, a message or another app shows *Pair with …?*, with the computer's name and address, before anything is sent. Before, it paired at once, and a link on a web page could pair your phone with someone else's server.
- **Replacing the computer you are paired with always asks,** however the link came, and says what it does: the notes already synced leave this device (they stay on the old computer), and changes not yet sent go to the new one.
- **Pairing again with the same computer,** for new addresses, lets it replace the old entry only when the computer shows the same certificate: a server that only claims your computer's name is a different one, and is not told who you were.

### Server

- **A stranger on your network cannot tie the server up** or keep your phones out. A connection that has not shown a paired device's token within 30 seconds is closed, a pairing waiting for Allow excepted, and when too many such connections are open the oldest go first. Your phones' connections are never let go to make room.
- **Revoking a device closes every connection it has open,** its live updates included, at once.
- **A notes volume that is unmounted while the server runs** stops the listing with an error until it is back, instead of being listed as an empty library, which would have taken every note off every phone.
- **The Devices page cannot be shown inside another site's page,** where a button could be put over it to trick you into revoking a phone.
- **Notes and pairing codes are sent so that no cache keeps them,** the browser's or a phone's own.
- **`KORGNOTE_LOG=debug`** writes more to the server's log.

### Notes from elsewhere

What a server, a shared folder or a note someone sent you contains is taken more carefully:

- **A note that crashed the app every time it opened** no longer does. A repeat written as `+2000000000y` made the reminders fail on every start, and the app could not be opened to remove it. A repeat or delay of more than 100,000 days, weeks, months or years is now ignored.
- **Notes with unusual lines open in seconds.** Some long lines, of spaces or of brackets, took from half a minute to several minutes to draw, or to be read for search and the calendar.
- **Sync takes only notes from a server:** visible `.org` files with names this device can store. A server can no longer place another kind of file beside your notes, remove a whole folder of them on an iPhone, or stop sync for good with a name too long to write.
- **On the desktop, a link in a note no longer opens a program or a script.** It shows why, and you can open the file yourself if you trust it. Documents open as before.

### Your secrets

- **The pairing token and the WebDAV password stay off your backups** even when the phone's key store fails. They were kept unencrypted in the settings then, which go to Google's backup; they now go in a file kept out of every backup.
- **iPhone backups no longer include the search index,** which holds your notes' titles, headings and tags. The notes themselves were already left out.
- **On the desktop, a pairing the system keyring will not unlock** stops sync and says so in Settings, rather than syncing with whatever answers on this computer's port 8080.

### Welcome

- **The welcome screens offer a folder only where notes can be kept in one,** on Android and the iPhone. On the desktop and the web the choice led to a step saying it could not be used.
