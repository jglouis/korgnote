Sync in the background on Android, fixes for sync and the calendar, and a security fix for the server. Update the server too: three of the fixes are in it.

### Sync

- **The app syncs with Android even while it is closed.** Every hour, and as soon as the network is back after an edit could not be sent. A meeting added on your computer now gets its reminder on the phone without opening the app, and an edit made offline reaches the server without waiting for you to open it again.
- **A phone no longer misses changes after the server restarts.** Once the restarted server had seen enough changes, a phone could be told only about the latest ones and stay out of date with no warning. This needs the 1.4.2 server.
- **A note deleted and made again elsewhere is no longer removed from the phone.** This needs the 1.4.2 server.
- **Edits not yet sent are kept if the app's sync records are damaged.** The server's version used to replace them; now yours is kept beside it as a conflict copy.

### Calendar

- **A missed repeating deadline shows as overdue.** It warned of its next date instead, and dropped out of the Overdue section.
- **The calendar moves on to the new day at midnight.** Left open overnight, it showed yesterday's overdue items until a note changed.

### Notes

- **Saving a note changes only the progress counts like `[2/5]` over what you edited.** Every count in the note was recalculated on each save, changing ones Emacs keeps differently. A heading's `:COOKIE_DATA:` (`todo`, `checkbox`, `recursive`) is now followed.
- **Enter in a source block no longer starts a list item.** A `- ` line in YAML or Markdown code is code, not an Org list.
- The welcome screen's *How to install the server* link opens the right part of the instructions again.

### Server and desktop

- **Security: other containers can no longer use the server's local port.** Inside Docker, port 8080 trusted any connection that said it came from `localhost`, so another container on the same Docker network could read and change every note and pair a device of its own. It now checks where the connection really comes from. Keep 8080 published on `127.0.0.1` only, as the instructions say.
- The desktop app keeps a pairing with another computer sealed with a key in the system's keychain, rather than in plain settings.
